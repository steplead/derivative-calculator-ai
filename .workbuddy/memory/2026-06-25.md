# 2026-06-25 工作日志

## 诊断"点击按钮没反应"

### 根因：Cloudflare 边缘 Rate Limiting Rule 拦截了 JS 静态资源

**用户报告**：在首页输入公式后点击 "Solve" 按钮没有任何反应。

**诊断过程**：
1. API 本身正常工作（curl 测试 `/api/derivative?equation=x^2` 返回 200 + 正确结果）
2. 首页 HTML 正常返回（38KB）
3. **所有 `_next/static/chunks/*.js` 文件返回 HTTP 429**（17 字节 `text/plain` 响应）
4. 429 响应特征：
   - `content-type: text/plain; charset=UTF-8`（不是 JSON → 不是 Next.js middleware 返回的）
   - `content-length: 17`
   - `retry-after: 10`
   - `server: cloudflare`
   - 无 `x-powered-by: Next.js`、无 `x-edge-runtime`
5. **结论**：这是 Cloudflare 边缘 Rate Limiting Rule 返回的，不是应用层 middleware

**为什么会发生**：
- 浏览器加载首页时，会并行请求 10+ 个 JS chunk 文件
- Cloudflare 边缘 Rate Limiting Rule 检测到同一 IP 在极短时间内发出大量请求
- 对大部分 JS 文件返回 429
- JavaScript 没有加载 → React 的 onClick 处理器没有挂载 → 点击按钮无反应

### 修复方案
需要用户在 Cloudflare 控制台修改或删除 Rate Limiting Rule：
- **选项 A（推荐）**：删除 Rate Limiting Rule，应用层 D1 rate limit（30/min 页面, 20/min API）已经足够防滥用
- **选项 B**：修改 Rule，排除 `/_next/*` 路径和静态文件扩展名
- **选项 C**：大幅提高阈值（如 50 req/10s）

### Cloudflare Rate Limiting Rule 配置位置
- Cloudflare Dashboard → 选择域名 derivativecalculatorai.com
- Security → WAF → Rate limiting rules
- 或 Security → WAF → Edge rules

- 该规则匹配条件：URI Path contains `/`（匹配所有请求）

### 验证结果（删除规则后）
所有 13 个静态资源全部 HTTP 200：
- ✅ 12 个 JS chunk 文件（最大 172KB fd9d1056，最小 631B main-app）
- ✅ 1 个 CSS 文件（67KB）
- ✅ API 正常返回计算结果

### 最终防滥用体系（三层，不依赖 Cloudflare 边缘限流）
1. **应用层 middleware**：UA 过滤（只拦脚本工具）+ API referer 检查
2. **D1 层**：rate_limit（页面 30/min, API 20/min）+ GLOBAL_QUOTA（30k/天）
3. **/embed/ 路径**：直接返回 cached 403

### 教训
- **Cloudflare Rate Limiting Rule 的 "URI Path contains /" 会匹配所有请求**，包括静态资源
- 浏览器加载一页需要 10+ 个并行 JS 请求，任何低于 50 req/10s 的阈值都会误杀
- 应用层 D1 rate limit 已经足够防滥用，不需要 Cloudflare 边缘限流规则
